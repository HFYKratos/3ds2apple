# iOS app

The SwiftUI shell for 3ds2apple. It displays the two 3DS screens, imports the
user's own ROM, drives the Zakuro runtime and exposes input, audio and frame
timing.

## Features

- Import a decrypted `.3ds` / `.cci` from the Files app; the file stays in the
  app's Documents directory and is never included in the app bundle.
- Upper screen 400×240 above lower screen 320×240, with the lower screen also
  acting as the 3DS touchscreen.
- On-screen buttons (D-pad, A/B/X/Y, L/R, Start/Select) plus GameController
  support (MFi, Xbox, DualSense).
- Audio through `zk_take_audio` and AVAudioEngine.
- Free-running frame loop capped at 60 Hz, decoupled from the display refresh.
- Performance HUD: `zk_run_frame`, both screen reads, image conversion and
  audio pump, in milliseconds.
- AOT status (`linked, active` / `linked, interpreting` / `interpreter shell`)
  and emulation speed relative to the 3DS 60 Hz timeline.

## Build

Requires macOS, Xcode, Rust with `aarch64-apple-ios`, and `xcodegen`.
See [docs/build.md](../../docs/build.md).

```bash
scripts/build-zakuro-ios.sh      # libzakuro_ios.a
scripts/build-ios-app.sh         # xcodegen + xcodebuild
scripts/package-ipa.sh ios/app/build/Release-iphoneos/3ds2apple.app 3ds2apple
```

The project is generated by XcodeGen; new source files are picked up when
`xcodegen generate` runs. The app is built unsigned and signed later on the
user's machine with Sideloadly or AltStore.

## Source layout

| File | Responsibility |
|---|---|
| `App.swift` | SwiftUI entry point |
| `ContentView.swift` | Screens, status/HUD, ROM actions, on-screen controls |
| `ROMSession.swift` | Runtime handle, ROM import, frame loop, input/audio plumbing |
| `ROMDocumentPicker.swift` | Files document picker wrapper |
| `ScreenImage.swift` | Reusable RGBA buffers and `CGImage` conversion |
| `InputState.swift` | Thread-safe merge of touch, overlay and controller input |
| `TouchControlsView.swift` | On-screen button overlay |
| `GameControllerInput.swift` | GameController-to-3DS button mapping |
| `AudioOutput.swift` | Ring buffer and AVAudioEngine output |
| `FrameTiming.swift` | Per-phase frame timing for the HUD |

`ios/ZakuroBridge.h` is the C bridge; all runtime calls must run on the single
serial queue owned by `ROMSession`.

## ROM handling

- The ROM is copied into `Documents/roms/`; saves and runtime data go under
  `Documents/data/`.
- The repository ships no ROMs, keys or game data.
- The app works only with decrypted dumps the user obtained from their own
  console.

## Known limitations

- The GPU path is currently Zakuro's software PICA200 renderer. It is the main
  frame-time cost; a Metal/Vulkan backend is under development.
- Games run only when a matching recompiled `libgame.a` is linked into the app.
  A generic interpreter-only build exists but is much slower.
- The first release does not include camera, microphone, online play or a
  full game library UI.
- iOS 16+ only; the app is not distributed through the App Store.

## Diagnostics

The status area includes:

```text
30 fps  2,247 frames  last: completed  audio: on
AOT: linked, active   speed: 50% of 60 Hz
loop: free-run · cap 60 fps
```

and a millisecond HUD for `total / run / read top / read bottom / CGImage /
audio`. These values make renderer and scheduler changes measurable on device.
