## 2. 图形高级选项契约

### 2.1 读取时机（决定 UI 文案与生效条件）

1. `ZAKURO_*` 六个开关都是 `OnceLock` 缓存，**进程内只读一次**；首次读取发生在第一次游戏加载后、渲染器构建/首个 draw 时。因此 `setenv` 必须在第一次 `zk_create`/`zk_create_presented` 之前完成——`App.init()` 足够；**运行中改动必须重启 App**（不是重新加载游戏），与现有 `gpuVertexShaders`/`preciseShading` 的“needs restart”一致。
2. `MVK_CONFIG_*` 由 MoltenVK 在首个实例/设备创建时读一次，同样要求 `App.init()` 之前。
3. 生效前提是硬件渲染路径（presenter 或 `zk_set_hardware_renderer`）。无 MoltenVK/设备创建失败时 `zk_create` 回落软件渲染，六个开关**全部无效且不报错**；诊断必须同时记录 `renderer_software`（已有）与本次开关，才能解释“开了没效果”。
4. 诊断 profile（`GPUDiagnosticsProfile`）与 `THREEDS2APPLE_RENDERER_OPTIONS` 优先于 Settings：`apply` 会跳过已在环境里/已在 `settingsEnvironment` 里的键（`MoltenVKTuning.swift:408-414`）。Settings 接线必须把键写入 `settingsEnvironment`，否则发布默认或 profile 可能覆盖用户选择。

### 2.2 候选逐个（6 个渲染优化）

| 变量 | 作用 | 读取位置 | 默认 / 生效前提 | 风险（画面？崩溃？仅性能？） | 进 Curated？ |
|---|---|---|---|---|---|
| `ZAKURO_SAFE_SKIPS` | 数学等价跳过“两个缓冲都不可能改变”的 draw，像素数与耗时记入 `safe_skips` | `patches/0006…:261-266` | 关；硬件路径，首个 draw 时读 | 等价性判断误判才会变画面（覆盖掩码/深度测试组合）；实现较保守；主要收益/风险都在性能 | **建议进** |
| `ZAKURO_DEDUPE_CAPTURE` | 同批次内“上次 capture 后未再绘制”的重复 capture 跳过，计数 `captures_skipped` | `patches/0005…:230-234` | 关；同上 | 若 guest 把 capture 当作同步点或含未跟踪写入，可能少一次拷贝；变画面风险低；主要性能 | **建议进** |
| `ZAKURO_MERGE_PASSES` | guest 没给深度缓冲的 draw，并入已有深度的 pass（强制关深度测试/写），计数 `merged` | `patches/0005…:222-226` | 关；同上 | 理论上画面不变；若 guest 依赖“无深度附件”的读取会露馅（罕见）；崩溃风险低；减少 pass 切换 | **建议进** |
| `ZAKURO_FAST_CLEARS` | 满屏 clear 走 `vkCmdClear*Image`，不再用 LOAD+STORE 的 render pass | `patches/0003…:122-125` | 关；同上 | 设计上只改写入路径；若目标同时被当 twin/需要保留旧内容，清屏语义差异可能露馅；中低风险；省带宽 | **建议进** |
| `ZAKURO_FAST_BARRIERS` | 目标切换后屏障收窄到 attachment/transfer 阶段，不再 `ALL_COMMANDS` | `patches/0003…:130-133` | 关；同上 | 只影响同步：同步不足会导致偶发花屏/撕裂（设备相关），不改变“正确同步”下的画面；**六项中风险最高**；纯性能 | **建议进（排在末尾）** |
| `ZAKURO_SORT_OPAQUE` | 可重排的 opaque draw 前后向排序（近者先画），早深度测试省片元；逐 draw 原因计数 `zk_sort:` | `patches/0004…:157-162` | 关；同上 | 重排必须不改变画面；同深度稳定排序、alpha test/部分掩码已放宽，但 blend/logic/stencil/GPU 顶点仍保持原序；边界条件出错会小面积错画；中风险 | **建议进** |

补充：`ZAKURO_FRAG_FAST_MATH` 已是发布默认（`MoltenVKTuning.swift:156-158`），不在本轮 Curated 列表；`ZAKURO_FRAG_SPECIALIZE` 只做诊断（`patches/0007…:4146-4160`），0.2.2 不进 UI。

### 2.3 MoltenVK 保守项（1 个组合开关，2 个 key）

| Key | 作用与取舍 | 默认（本机未复核） | 建议 |
|---|---|---|---|
| `MVK_CONFIG_PREFILL_METAL_COMMAND_BUFFERS=1` | 把 Metal 命令编码前移到 `vkEndCommandBuffer`，每个 Vulkan CB 对应一个 Metal CB；CPU 峰值前移、内存占用升高（MoltenVK 文档 main 分支为 0/1/2 枚举，默认 `0`） | 0 | 与下一项一起作为**一个** UI 开关，默认关 |
| `MVK_CONFIG_MAX_ACTIVE_METAL_COMMAND_BUFFERS_PER_QUEUE=8` | 限制每队列并发 Metal CB 数量（文档默认 64），收紧预填带来的内存/并行度 | 64 | 同上；A/B 判定不足 5% 就只留在诊断 profile |

同样属于“候选但**不建议**进 curated”：

- `MVK_CONFIG_FAST_MATH_ENABLED`：直接改 Metal 着色器数学（main 文档为 0/1/2 枚举、默认 2），**会改变画面**；且 `ZAKURO_FRAG_FAST_MATH` 已在片段着色器层默认开，叠加无新增语义。只在诊断 profile 里做对照。
- `MVK_CONFIG_USE_METAL_ARGUMENT_BUFFERS`：文档（main）默认已为 1，显式再设无意义；1.4.2 默认值待复核，复核前不进 UI。
- `MVK_CONFIG_PREALLOCATE_DESCRIPTORS`：1.4.2 allowlist 中存在，但 main 分支文档已无此键（版本差异）；预期默认已开、无可测量收益 ⇒ 不进 UI。

### 2.4 不进用户设置的诊断开关（保持 Debug/诊断 IPA 通道）

`ZAKURO_GPU_TIMES`（时间戳查询有固定成本）、`ZAKURO_MEASURE_NOBLEND` / `_FLAT` / `_TEXONLY`（**画面故意错误**的测量 profile）、`THREEDS2APPLE_DIAG_RENDER_SCALE`（2x3x 测量）、以及 0.1.3 之前的 `ZAKURO_GPU_SHADERS`/`CPU_SHADERS`/`FLOAT_DEPTH`/`DEPTH_BLITS`/`STATIC_BLEND`/`GENERIC_SHADERS`/`INTERPRET_SHADERS`/`WAIT_FOR_SHADERS`。它们继续只通过 `THREEDS2APPLE_RENDERER_OPTIONS` 与 `scripts/build-gpu-diagnostic-ipa.sh` 的 profile 使用（`scripts/README.md` §GPU A/B）。现有 Graphics→Experimental 的 GPU vertex shading / Precise shading 两项**不迁移、不改名**。

### 2.5 Curated 列表建议（0.2.2 进 Settings→Graphics→Advanced 的最终清单）

分组 1「渲染优化 / Renderer optimisations」，6 个 toggle，按风险从低到高排列，全部默认关、标注实验性、需重启：

## 3. 金手指（cheats）可行性

### 3.1 结论：已编入、每帧自动执行、0.2.2 不需要新 tick

- linked iOS runtime 走 zakuro-core（`pub mod cheats;` 无 feature gate），`System::run_frame` 在每帧开头（HID 更新后、CPU 步进前）调用 `cheats::run(self)`；`zk_run_frame` 就是 `system.run_frame()`。⇒ **无需 run-loop 接线、无需新增 tick 调用**。
- 加载点：`zk_create`/`zk_create_presented` → `loader::load`，在 `config.data_dir` 存在时读 `<data_dir>/cheats/<program_id:016X>.txt`。⇒ 文件放在该路径后**重新加载游戏即可生效，零 Rust 改动**（路线 A）。
- 格式与上游/Citra/Azahar 一致：`[名称]`、`*citra_enabled`、`*备注`、`XXXXXXXX YYYYYYYY`；解析容忍行首尾空白与 NUL（`cheats.rs:95-125`）。
- 每帧执行上限 100,000 步/项（`cheats.rs:51`）；越界地址写入被 `mapped()` 拦下（`:252-254`）；A0（软件 + readback）与 A1（presenter）两条路径都覆盖；快进/多帧时按“每次 `zk_run_frame` 一帧”执行（按模拟帧，不按呈现帧）。
- 上游 `enhancements`（社区代码库，`include_str!` 2,902 B）也被编入 zakuro-core；iOS 侧 `Config.enhancements` 恒为空 ⇒ 不会自动启用，但数据在二进制里（见 §4 风险 6）。

### 3.2 存储格式与方案

推荐格式（与 Citra/Azahar 文本互通，用户可从已有工具整段复制）：

```text
[示例项]
*说明文字（可选）
XXXXXXXX YYYYYYYY
XXXXXXXX YYYYYYYY
```

- 文件名 `<TITLEID>.txt`，16 位大写十六进制（= App 现有 `GameInfo.titleID`/`%016llX`）。UTF-8，LF 或 CRLF 均可（解析 `trim()`）。上限建议：文件 ≤ 256 KiB、≤128 项、每项 ≤1024 行（防止误粘大文件）。
- **路线 A（零改动兜底）**：`Documents/data/<save namespace>/cheats/<TITLEID>.txt`。缺点：`SaveDataStore.batterySaveFiles` 枚举 data_dir 下**所有普通文件**（`SaveDataStore.swift:79-99`），cheats 会被卷进存档导出/导入；且运行中改文件不生效。
- **路线 B（推荐，P1 目标）**：新增 ABI，App 独占 `Documents/Cheats/<TITLEID>.txt` 作为唯一权威文件（不放进 data_dir），支持 Files app/分享面板导入导出、单文件备份；运行时只通过显式路径读。

### 3.3 C ABI 草案（全部在 runtime 串行队列调用；沿用现有错误约定）

| 签名 | 语义 | 返回 / 错误码 |
|---|---|---|
| `int32_t zk_cheats_load(zk_system_t system, const char *path)` | 读 UTF-8 文件并解析，替换当前 player cheats（保留 builtin）；立即按新启用集合生效 | 成功 = 条数（≥0）；`-1` NULL 句柄；`-2` NULL/非 UTF-8 路径；`-3` 读取失败（原因进 `zk_last_error`）；`-4` 超上限 |
| `int32_t zk_cheats_save(zk_system_t system, const char *path)` | 以 Citra 格式写回（含 `*citra_enabled` 标记）；实现须“临时文件 + rename”原子写（`cheats::save` 是直接 `fs::write`，不能直接复用） | `0` 成功；负值同上 |
| `int32_t zk_cheats_count(zk_system_t system)` | player cheats 条数 | `≥0`；`-1` NULL 句柄 |
| `const char *zk_cheats_json(zk_system_t system)` | thread-local JSON（schema 1，线程内有效，需拷贝）：`{"schema":1,"cheats":[{"name":"…","enabled":true,"lines":2,"invalidLines":0}]}` | 指针或 NULL（无句柄）；错误语义同 `zk_keyboard_request_json`（README “Software keyboard” 一节） |
| `int32_t zk_cheats_set_enabled(zk_system_t system, int32_t index, int32_t enabled)` | 开/关某项（下一帧生效） | `0`；`-1` NULL；`-2` 越界；`-3` 拒绝（builtin） |

- **不新增 tick 函数**（`zk_run_frame` 已覆盖）。可选 P2：`zk_cheats_enabled_count` 供诊断一行。
- 语义细节：关闭某项**不会回滚**它已写入的字节（上游注释：与 Citra 一致，“free money stays free money”）；读档不恢复“启用集合”；`zk_destroy` 后句柄失效。头文件加进 `ios/ZakuroBridge.h`（与 `zk_keyboard_*` 同段），Rust 侧放 `ios/zakuro-ios/src/cheats.rs`。

### 3.4 每帧接入点（数据流）

1. `ROMSession` runtimeQueue 帧循环 → `zk_run_frame`（`ROMSession.swift:2523/2637`）。
2. `System::run_frame`：HID 采样 → **`cheats::run(self)`** → CPU 步进至帧边界 → `end_frame()`（`zakuro-core/src/lib.rs:326-345`）。
3. turbo/帧率上限的多余帧：每次 `zk_run_frame` 都执行一次 ⇒ 快进时金手指按模拟帧连续生效。
4. 暂停/后台：帧循环停止 ⇒ 不执行。
5. 存档：`state/mod.rs:117-122` 只保存 builtin 的 overwrote 字节；player cheat 的写入就是普通 RAM 写，随 RAM 进 state；读档后按当前启用集合继续每帧执行。
6. 代码补丁类：`cheats.rs:229-240` 在发现 text/module 被改写后调 `recompiled::Library::check`，自检能力由 `origins` 表决定（`recompiled.rs:468`）；早期 3dsrecomp 无自检时仅告警。

### 3.5 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 代码补丁类在 AOT 下可能不生效或回退解释器 | 帧率下降；与“手机端只跑 AOT”原则冲突 | P1 只承诺**数据类**金手指；UI 与文档说明；诊断记录解释器回退告警 |
| 每帧成本 / 超长码 | 掉帧 | 100,000 步上限；perf 观测；UI 提示 |
| 错地址或坏值写坏 guest 状态 | 游戏异常、存档损坏 | `mapped()` 越界保护；启用前提示先备份存档 |
| 存档兼容 | 读档后与“存档时的启用集合”不一致 | 文档说明；诊断记录启用项数 |
| 路线 A 把 cheats 卷进存档导出 | 用户存档包混入代码文件 | 采用路线 B |
| 上游 `enhancements.txt`（社区代码库，含商业标题 ID/名称）被编入二进制 | 合规风险（AGENTS §2.5/§2.14：不内置任何代码数据库） | 建议 iOS 构建剔除该数据（feature 或 patch）或至少不提供任何入口；**待 Lead 决策** |
| 在线公平性 / rom hack | — | 不承诺；仅用户自有 ROM、用户自备代码 |
| 命名/本地化 | UI 出现商业游戏名 | 文件由用户提供；UI 只显示文件名/TITLEID，不内置任何名称 |

## 4. 未确认风险 / 待决策

1. **用户预期**：6+1 个开关全部默认关是否符合预期（本轮计划 §7.4 待答）；是否需要“推荐组合”一键项（建议先不做）。
2. **无真机 A/B 数据**：本仓库没有 0.1.3 之后各候选的真机测量结论；5% 门槛与“任何画面变化即否决”沿用 `scripts/README.md`。MVK 组合开关建议先做一轮 A/B 再决定是否保留在 UI。
3. **MoltenVK 1.4.2 默认值未在本机复核**（框架二进制只在构建机 macOS VM）：`PREFILL`/`MAX_ACTIVE`/`USE_METAL_ARGUMENT_BUFFERS`/`PREALLOCATE_DESCRIPTORS` 的默认取自 main 分支文档，1.4.2 可能不同；`FAST_MATH_ENABLED` 在 main 是 0/1/2 枚举（默认 2），1.4.2 可能是 Boolean。因此三项 MVK 候选全部不进 UI 直到复核。
4. **cheats 已编入的旁证**：`.a` 字符串里 `citra_enabled` 未出现（常量比较被内联成立即数，不能据此判否），依据是源码路径 + cheats 独有日志串。建议 P1 实施时用宿主测试和真机 smoke 再确认（`load` 后 `zk_cheats_count` 应等于文件项数）。
5. **代码补丁类与 AOT 原则的冲突**：需要产品决策（是否允许回退解释器、是否只在诊断构建放开）。
6. **`enhancements.txt` 合规处置**：剔除（干净二进制）vs 保留（不暴露入口）——需 Lead/用户决定；会影响 iOS 构建脚本与补丁清单。
7. **文件可达性**：iOS 沙盒下 `Documents` 可写并可通过 Files app/分享面板导入；是否上 iCloud 备份、是否允许从启动器推送 cheats 文件，本轮不展开。
