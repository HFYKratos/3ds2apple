## 2. 图形高级选项契约

### 2.1 读取时机（决定 UI 文案与生效条件）

1. `ZAKURO_*` 六个开关都是 `OnceLock` 缓存，**进程内只读一次**；首次读取发生在第一次游戏加载后、渲染器构建/首个 draw 时。因此 `setenv` 必须在第一次 `zk_create`/`zk_create_presented` 之前完成——`App.init()` 足够；**运行中改动必须重启 App**（不是重新加载游戏），与现有 `gpuVertexShaders`/`preciseShading` 的“needs restart”一致。
2. `MVK_CONFIG_*` 由 MoltenVK 在首个实例/设备创建时读一次，同样要求 `App.init()` 之前。
3. 生效前提是硬件渲染路径（presenter 或 `zk_set_hardware_renderer`）。无 MoltenVK/设备创建失败时 `zk_create` 回落软件渲染，六个开关**全部无效且不报错**；诊断必须同时记录 `renderer_software`（已有）与本次开关，才能解释“开了没效果”。
4. 诊断 profile（`GPUDiagnosticsProfile`）与 `THREEDS2APPLE_RENDERER_OPTIONS` 优先于 Settings：`apply` 会跳过已在环境里/已在 `settingsEnvironment` 里的键（`MoltenVKTuning.swift:408-414`）。Settings 接线必须把键写入 `settingsEnvironment`，否则发布默认或 profile 可能覆盖用户选择。

### 2.2 候选逐个（6 个渲染优化）

| 变量 | 作用 | 读取位置 | 默认 / 生效前提 | 风险（画面？崩溃？仅性能？） | 进 Curated？ |
|---|---|---|---|---|---|
| `ZAKURO_SAFE_SKIPS` | 数学等价跳过“两个缓冲都不可能改变”的 draw，像素数与耗时记入 `safe_skips` | `patches/0006…:261-266` | 关；硬件路径，首个 draw 时读 | 等价性判断误判才会变画面（覆盖掩码/深度测试组合）；实现较保守；主要收益/风险都在性能 | **建议进** |
| `ZAKURO_DEDUPE_CAPTURE` | 同批次内“上次 capture 后未再绘制”的重复 capture 跳过，计数 `captures_skipped` | `patches/0005…:230-234` | 关；同上 | 若 guest 把 capture 当作同步点或含未跟踪写入，可能少一次拷贝；变画面风险低；主要性能 | **建议进** |
| `ZAKURO_MERGE_PASSES` | guest 没给深度缓冲的 draw，并入已有深度的 pass（强制关深度测试/写），计数 `merged` | `patches/0005…:222-226` | 关；同上 | 理论上画面不变；若 guest 依赖“无深度附件”的读取会露馅（罕见）；崩溃风险低；减少 pass 切换 | **建议进** |
| `ZAKURO_FAST_CLEARS` | 满屏 clear 走 `vkCmdClear*Image`，不再用 LOAD+STORE 的 render pass | `patches/0003…:122-125` | 关；同上 | 设计上只改写入路径；若目标同时被当 twin/需要保留旧内容，清屏语义差异可能露馅；中低风险；省带宽 | **建议进** |
| `ZAKURO_FAST_BARRIERS` | 目标切换后屏障收窄到 attachment/transfer 阶段，不再 `ALL_COMMANDS` | `patches/0003…:130-133` | 关；同上 | 只影响同步：同步不足会导致偶发花屏/撕裂（设备相关），不改变“正确同步”下的画面；**六项中风险最高**；纯性能 | **建议进（排在末尾）** |
| `ZAKURO_SORT_OPAQUE` | 可重排的 opaque draw 前后向排序（近者先画），早深度测试省片元；逐 draw 原因计数 `zk_sort:` | `patches/0004…:157-162` | 关；同上 | 重排必须不改变画面；同深度稳定排序、alpha test/部分掩码已放宽，但 blend/logic/stencil/GPU 顶点仍保持原序；边界条件出错会小面积错画；中风险 | **建议进** |

补充：`ZAKURO_FRAG_FAST_MATH` 已是发布默认（`MoltenVKTuning.swift:156-158`），不在本轮 Curated 列表；`ZAKURO_FRAG_SPECIALIZE` 只做诊断（`patches/0007…:4146-4160`），0.2.2 不进 UI。

### 2.3 MoltenVK 保守项（1 个组合开关，2 个 key）

| Key | 作用与取舍 | 默认（本机未复核） | 建议 |
|---|---|---|---|
| `MVK_CONFIG_PREFILL_METAL_COMMAND_BUFFERS=1` | 把 Metal 命令编码前移到 `vkEndCommandBuffer`，每个 Vulkan CB 对应一个 Metal CB；CPU 峰值前移、内存占用升高（MoltenVK 文档 main 分支为 0/1/2 枚举，默认 `0`） | 0 | 与下一项一起作为**一个** UI 开关，默认关 |
| `MVK_CONFIG_MAX_ACTIVE_METAL_COMMAND_BUFFERS_PER_QUEUE=8` | 限制每队列并发 Metal CB 数量（文档默认 64），收紧预填带来的内存/并行度 | 64 | 同上；A/B 判定不足 5% 就只留在诊断 profile |

同样属于“候选但**不建议**进 curated”：

- `MVK_CONFIG_FAST_MATH_ENABLED`：直接改 Metal 着色器数学（main 文档为 0/1/2 枚举、默认 2），**会改变画面**；且 `ZAKURO_FRAG_FAST_MATH` 已在片段着色器层默认开，叠加无新增语义。只在诊断 profile 里做对照。
- `MVK_CONFIG_USE_METAL_ARGUMENT_BUFFERS`：文档（main）默认已为 1，显式再设无意义；1.4.2 默认值待复核，复核前不进 UI。
- `MVK_CONFIG_PREALLOCATE_DESCRIPTORS`：1.4.2 allowlist 中存在，但 main 分支文档已无此键（版本差异）；预期默认已开、无可测量收益 ⇒ 不进 UI。

## 3. 金手指（cheats）——运行时 ABI 已实现

> 实现状态（2026-11-26）：本节的 C ABI 与上游 enhancements 合规剔除已落地。改动：
> `ios/zakuro-ios/src/cheats.rs`（新模块，5 个 C ABI 函数 + 宿主测试）、
> `ios/ZakuroBridge.h`（声明、常量与错误码）、`ios/zakuro-ios/src/lib.rs`（`mod cheats;` 与
> crate 文档）、`ios/zakuro-ios/patches/0011-remove-enhancements-data.patch`、
> `scripts/build-zakuro-ios.sh`（构建期合规检查）。App 侧的文件导入、列表与开关 UI
> 不在本任务范围（settings-ui 后续接入）。

### 3.1 结论：已编入、每帧自动执行、不需要新 tick

- linked iOS runtime 走 zakuro-core（`pub mod cheats;` 无 feature gate），`System::run_frame`
  在每帧开头（HID 更新后、CPU 步进前）调用 `cheats::run(self)`；`zk_run_frame` 就是
  `system.run_frame()`。⇒ **无需 run-loop 接线、无 tick 函数**：`zk_cheats_*` 只改
  `System::cheats`，下一帧即生效。
- 格式与上游/Citra/Azahar 一致：`[名称]`、`*citra_enabled`、`*备注`、`XXXXXXXX YYYYYYYY`；
  解析直接复用 `zakuro_core::cheats::parse`（容忍行首尾空白、NUL 与 CRLF）。
- 每帧执行上限 100,000 步/项（上游 `MOST_STEPS`）；越界地址写入被 `mapped()` 拦下；A0
  （软件 + readback）与 A1（presenter）两条路径都覆盖；快进/多帧时按“每次 `zk_run_frame`
  一帧”执行（按模拟帧，不按呈现帧）。
- 显式路径（路线 B）：不依赖 `Config::data_dir` 自动加载；App 传入
  `Documents/Cheats/<TITLEID>.txt`，运行时不写任何未被点名的路径。

### 3.2 存储格式与约定（最终）

文件格式 = Citra/Azahar 文本，用户可从已有工具整段复制：

```text
[示例项]
*说明文字（可选）
XXXXXXXX YYYYYYYY
XXXXXXXX YYYYYYYY
```

| 约定 | 值 / 说明 |
|---|---|
| 路径 | 由 App 决定（本设计：`Documents/Cheats/<TITLEID>.txt`，16 位大写十六进制标题 ID），运行时不拼 `data_dir` |
| 编码 | UTF-8；非 UTF-8 字节按 `from_utf8_lossy` 变成 U+FFFD（与上游一致，不拒绝整文件）；LF/CRLF 均可 |
| 上限 | 文件 ≤ 256 KiB、≤128 项、每项 ≤1024 行（`ZK_CHEATS_MAX_*`，超出 `zk_cheats_load` 返回 `-4`，旧列表保持不变） |
| 写回 | 启用项带 `*citra_enabled`；只写 player 项（builtin 不落用户文件）；先写同目录临时文件、`sync_all` 后 rename，崩溃不留半截文件 |
| 目录 | 保存时自动 `create_dir_all` 父目录，首次保存进新的 `Documents/Cheats` 可直接用 |
| JSON | 见 §3.3；文档 ≤ 256 KiB（`ZK_CHEATS_JSON_MAX_BYTES`），每项名字截到 256 UTF-8 字节（字符边界） |

### 3.3 C ABI 最终签名（已实现；头文件 `ios/ZakuroBridge.h` §cheat codes）

| 签名 | 语义 | 返回 / 错误码 |
|---|---|---|
| `int32_t zk_cheats_load(zk_system_t system, const char *path)` | 读 UTF-8 文件、用运行时自己的 parser 解析，替换 player cheats（保留 builtin）；启用项下一帧起生效；被拒绝时旧列表不变 | 成功 = 条数（≥0）；`-1` NULL 句柄；`-2` NULL/非 UTF-8 路径；`-3` 读取失败；`-4` 超上限（原因进 `zk_last_error`） |
| `int32_t zk_cheats_save(zk_system_t system, const char *path)` | 以 Citra 格式写回（含 `*citra_enabled`），临时文件 + rename 原子写，必要时创建父目录 | `0`；`-1`/`-2`/`-3`（写失败也是 `-3`，原因进 `zk_last_error`） |
| `int32_t zk_cheats_count(zk_system_t system)` | player cheats 条数（不含 builtin） | `≥0`；`-1` NULL 句柄 |
| `const char *zk_cheats_json(zk_system_t system)` | thread-local JSON（schema 1）：`{"schema":1,"cheats":[{"name":"…","enabled":true,"lines":2,"invalidLines":0}]}`；`invalidLines` = 运行时保留并写回但不执行的坏行；builtin 不列出；指针在同线程下次调用前有效（同 `zk_keyboard_request_json` 模式） | 指针或 NULL（NULL 句柄；并清掉本线程旧文档） |
| `int32_t zk_cheats_set_enabled(zk_system_t system, int32_t index, int32_t enabled)` | `index` = `zk_cheats_json` 的报告顺序（player 顺序）；下一步生效 | `0`；`-1` NULL；`-2` 越界（含负 index）；`-3` 拒绝 builtin（本构建没有 builtin） |

- **不新增 tick 函数**（`zk_run_frame` 已覆盖）。`zk_cheats_save` 不能直接复用上游
  `cheats::save`（直接 `fs::write`），因此用同目录临时文件 + rename 自写。
- 语义细节：关闭某项**不回滚**它已写入的字节（与 Citra 一致）；读档不恢复“启用集合”
  （启用集合只存在于文件与当前内存）；`zk_destroy` 后句柄失效。
- 线程/错误：与其它带句柄调用一致，走 runtime 串行队列；成功的 load/save/enable 清空
  `zk_last_error`。

### 3.4 每帧接入点（不变）

1. App 帧循环（ROMSession runtimeQueue）→ `zk_run_frame`。
2. `System::run_frame`：HID 采样 → **`cheats::run(self)`** → CPU 步进至帧边界 → `end_frame()`
   （`zakuro-core/src/lib.rs:326-345`）。
3. turbo/帧率上限的多余帧：每次 `zk_run_frame` 都执行一次 ⇒ 快进时按模拟帧连续生效。
4. 暂停/后台：帧循环停止 ⇒ 不执行。
5. 存档：`state/mod.rs:117-122` 只保存 builtin 的 overwrote 字节；player cheat 的写入是普通
   RAM 写、随 RAM 进 state；读档后按当前启用集合继续每帧执行。
6. 代码补丁类：`cheats.rs:229-240` 在 text/module 被改写后调 `recompiled::Library::check`，
   自检能力由 `origins` 表决定（`recompiled.rs:468`）；早期 3dsrecomp 无自检时仅告警。

### 3.6 enhancements 合规剔除（已实现）

- `patches/0011-remove-enhancements-data.patch`：把

## 4. 未确认风险 / 待决策

1. **用户预期**：6+1 个开关全部默认关是否符合预期（本轮计划 §7.4 待答）；是否需要“推荐组合”一键项（建议先不做）。
