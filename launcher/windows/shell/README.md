# Base shell template IPA (ROM-free, pinned)

The Windows launcher installs **one** app: the ROM-free shell template plus every
built game's GamePack, signed as a single IPA. This directory is where the
distribution puts the template and its pinned identity file; the launcher
composes the installable IPA at install time.

## Files expected in a launcher package

    Shell/
      manifest.json              pinned identity of the template (see manifest.example.json)
      3ds2apple-shell.ipa        unsigned, ROM-free shell template IPA built on macOS

Both files are build products: they are **not committed** to git. The template
must have an empty GameCatalog.json, no Frameworks/GamePack-*.dylib and no Roms/
entries. The launcher refuses a template that contains game data and verifies the
SHA-256/size before composing.

## How the app IPA is produced on Windows

    template.ipa (pinned, ROM-free)
      + Frameworks/GamePack-<TITLEID>.dylib   for every built game
      + GameCatalog.json (schema v2, generated by 3ds2apple-pack catalog)
      -> composed unsigned IPA (workspace/work/app-ipa/)
      -> plumesign sign --package ... --apple-id --register-and-install --udid ...
      -> installed app; the IPA signature covers the nested dylibs

Only the user's own Apple ID (entered in Impactor) signs it. Adding or removing a
game recomposes and reinstalls the IPA; already-pushed ROM data under
Documents/Games/<TITLEID>/ survives the overwrite install.

## How to produce the shell template IPA (macOS host)

The shell must be the launcher-aware build (task-17): it reads the bundle
GameCatalog.json, loads Frameworks/GamePack-<TITLEID>.dylib and runs the ROM from
Documents/Games/<TITLEID>/GameRom.cci. The template contains **no** ROM and an
empty catalogue. Use the project scripts on the macOS build machine:

    # 1. build the unsigned shell app (no catalog entries / no bundled games)
    PATH=/usr/local/bin:$PATH scripts/build-ios-app.sh --keep-project
    # 2. package the unsigned IPA
    scripts/package-ipa.sh <app path> 3ds2apple-shell

Record the pinned identity and put the files under Shell/:

    $ipa = "3ds2apple-shell.ipa"
    $sha = (Get-FileHash -Algorithm SHA256 $ipa).Hash.ToLower()
    $bytes = (Get-Item $ipa).Length
    @{
      schemaVersion = 1
      fileName = $ipa
      version = "0.2.0"
      bundleId = "com.kratos.3ds2apple"
      sha256 = $sha
      bytes = $bytes
      minIosVersion = "16.0"
    } | ConvertTo-Json | Set-Content Shell/manifest.json

Then run tools/prepare-dist.ps1. The launcher verifies the template hash/size,
injects the packs + catalogue and signs the composed IPA with the official
plumesign.

## Template identity rules (validated by the launcher)

The launcher refuses to compose/sign a template unless all of these hold:
- Shell/manifest.json: version >= 0.2.0-beta1 and build >= 9;
- the IPA's Info.plist CFBundleShortVersionString / CFBundleVersion are readable
  (binary or XML plist) and meet the same thresholds;
- bundle GameCatalog.json is schemaVersion 2 with an empty games list;
- no Roms/ entries (game data is pushed separately).

## Safety

- Never put a ROM, keys, BIOS, GameRom data or GamePack.dylib into the template.
- Packs are injected only from the user's own built library; the composed IPA
  carries no game data, only code.
- The IPA is unsigned; the user's own Apple ID signs it via Impactor.
- Do not commit the IPA or the manifest: they are per-build artifacts.
