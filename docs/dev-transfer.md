# Dev file transfer (VM / CachyOS / VPS / Windows-WSL)

> Status: task-15 implementation, 2026-11-14 · owner: transfer-infra · not committed yet (Lead review)
>
> Scope: moving dev artifacts (shell IPA, per-game AOT IPA, GamePack dylibs, evidence
> archives) between the macOS build VM, the CachyOS host, the VPS and the Windows/WSL
> workstation. This page records **measured** numbers from 2026-11-14 and the one-command
> helper [scripts/dev-transfer.sh](../scripts/dev-transfer.sh).
>
> This page contains no ROM, IPA or game content, no keys and no credentials.

## 0. TL;DR

| Need | Use | Command |
|---|---|---|
| Move a file from the macOS VM to the VPS (fast leg) | VPS relay push | CachyOS host: **scripts/dev-transfer.sh push --vm "~/3ds2apple/IPA/<artifact>" --ipa** |
| Get that file onto Windows/WSL | VPS relay fetch (HTTPS, resumable) | WSL: **scripts/dev-transfer.sh fetch &lt;url&gt; &lt;dest&gt; --sha256 &lt;hash&gt;** |
| Install an IPA on the iPhone | SideStore source generated by **--ipa** | SideStore -> Sources -> + (URL is printed by push) |
| Transfer 1.5 GB fast | direct LAN **only** (see §6) | **scripts/dev-transfer.sh lan fetch/push ...** |
| Clean up | | **scripts/dev-transfer.sh clean &lt;token&gt;** |

**Bottom line (measured): the VPS relay is fast in the push direction (3.0-4.9 MB/s) and
slow in the fetch direction (0.19-0.42 MB/s, samples vary), because this VPS has a
~4 Mbps public egress cap. For a 1.5 GB IPA the relay therefore takes about 1.1-2.3 h -
the same or worse than the old DSH-relay wait, so the relay alone does **not** solve the
1.5 GB case. What it does give: one command, a resumable download, sha256 end to end,
random tokens and enforced cleanup. The two real fixes are same-LAN transfer (seconds)
or a VPS with more egress bandwidth (~5-7 min).**

## 1. Topology and why the old path is slow

~~~
  macOS build VM (QEMU on CachyOS host, ssh localhost:2222)
        |  scp over QEMU hostfwd localhost      ~15.5 MB/s measured
        v
  CachyOS build host (kratos-cachyos, 192.168.1.8/24, public IPv6)
        |  ssh root@47.115.170.160 + rsync       ~4.7-4.9 MB/s measured (upload)
        v
  VPS 47.115.170.160 (Tencent Cloud, nginx, Let's Encrypt, /var/www/ios)
        |  HTTPS download                       ~0.42 MB/s measured (VPS egress cap)
        v
  Windows / WSL workstation (192.168.10.167, WSL2 mirrored networking)
~~~

- The two machines are on **different networks** (CachyOS 192.168.1.8 with public IPv4
  106.44.27.183, Windows/WSL 192.168.10.167 with public IPv4 113.200.219.22) and neither
  has a reachable inbound port, so a direct connection is not possible today.
- Today's transfer path is the **public DSH relay**, also hosted on the same VPS. Its
  measured end-to-end rate for the 1.5 GB IPA was about 1 hour = ~0.42 MB/s: that is
  exactly the VPS egress cap, so the relay is not "extra slow" - the VPS is.
- The cap is shared: the DSH relay session itself also exits through this VPS, so the
  measured VPS -> client rate varies from 0.19 to 0.42 MB/s depending on how busy the
  relay is at that moment. Plan for the pessimistic end.
- The VPS **upload** direction is *not* capped the same way: pushing to the VPS runs at
  ~4.7-4.9 MB/s (38-39 Mbps, the CachyOS home uplink). Only VPS -> client downloads are
  limited to ~3.4 Mbps.
- 8 parallel HTTP range streams from the VPS aggregate to the same ~0.37 MB/s: the cap is
  per instance, not per connection, so download parallelism does not help.
- Both client sides have fast internet otherwise: 20 MiB from a Chinese mirror measured
  9.5 MB/s (CachyOS) and 9.7 MB/s (WSL). The bottleneck is only the VPS egress.

## 2. Measured numbers (2026-11-14, 32 MiB synthetic test file)

| Leg | Command | Time | Rate | 1.5 GB projection |
|---|---|---|---|---|
| VM -> CachyOS host | scp 32 MiB over localhost:2222 | 2.17 s | 15.5 MB/s | ~1.6 min |
| CachyOS host -> VPS | scp 32 MiB as root | 6.87 s | 4.88 MB/s | ~5.1 min |
| CachyOS host -> VPS (helper) | push 32 MiB via rsync over ssh | 11.2 s | 3.01 MB/s | ~8.3 min |
| VPS -> CachyOS host | curl 32 MiB over HTTPS | >60 s (capped) | 0.42 MB/s | ~58 min |
| VPS -> WSL | curl 32 MiB over HTTPS | 79.9 s | 0.42 MB/s | ~58 min |
| VPS -> local (helper fetch, 32 MiB) | fetch via curl (resume-capable) | 165.2 s | 0.20 MB/s | ~122 min |
| VPS -> client, re-sample (3.9 MiB shell IPA) | curl x3 (WSL 2x, CachyOS 1x) | 15.7-20.5 s | 0.19-0.25 MB/s | ~100-130 min |
| VPS -> 8 parallel curls | 8 x 4 MiB ranges, 20 s window | 20 s | 0.37 MB/s aggregate | no gain |
| WSL -> Chinese mirror | curl 20 MiB from Tsinghua | 2.15 s | 9.7 MB/s | - |
| CachyOS -> Chinese mirror | curl 20 MiB from Tsinghua | 2.20 s | 9.5 MB/s | - |
| Full VPS relay, 1.5 GB | push then fetch | ~5.5-8.7 min + ~60-130 min | - | **~1.1-2.3 h** |

The fetch samples above were taken at different times and the DSH relay session was also
using the same VPS egress; treat 0.19-0.42 MB/s as the honest range and plan for the
pessimistic end. VPS facts checked while measuring: 40 GB disk / 15 GB free, nginx 1.18 serving
/var/www/ios over HTTPS (valid Let's Encrypt cert, HTTP plain 80 does not serve /ios),
/var/www/ios/tmp is not listable (autoindex off, HTTP 403), /var/lib/dev-transfer is the
new non-web index directory.

## 3. Quick start

### 3.1 Push (run on the CachyOS build host)

~~~bash
# Bundled-ROM IPA from the macOS VM -> random one-time VPS path + SideStore source
scripts/dev-transfer.sh push --vm "~/3ds2apple/IPA/3ds2apple-pokemon-y-bundled-rom.ipa" --ipa
~~~

The command prints the https URL, the sha256, the expiry and the exact cleanup command.
It also writes a SideStore source.json next to the artifact when **--ipa** is used.

~~~bash
# Smaller file already on the CachyOS host (no VM leg)
scripts/dev-transfer.sh push build/game/device/GamePack.dylib

# Reproject the SideStore source for an existing token
scripts/dev-transfer.sh side-load <token>
~~~

### 3.2 Fetch (run on Windows/WSL; no SSH key needed)

~~~bash
scripts/dev-transfer.sh fetch https://47.115.170.160/ios/tmp/<token>/<name>.ipa \
    IPA/<name>.ipa --sha256 <hash>
~~~

The download resumes automatically: rerun the same command after an interruption
(curl --continue-at -). Without **--sha256** the published <url>.sha256 sidecar is used;
a mismatch is a hard failure and the file is kept for inspection.

### 3.3 SideStore install (iPhone; no Windows download leg)

1. On the iPhone: **SideStore -> Sources -> +** and paste the **source:** URL printed by
   push --ipa (it ends in /source.json under the same random token).
2. Pull to refresh the source, open the app entry and tap **Install**. Keep the iPhone on
   power/Wi-Fi; the download rate is currently the VPS egress rate (§1), i.e. roughly
   60-130 min for a 1.5 GB IPA.
3. After the app is installed run **scripts/dev-transfer.sh clean <token>** so the IPA is
   no longer reachable.

The SideStore source is temporary and has a unique identifier derived from the token; it
only lists the one artifact.

### 3.4 Cleanup (mandatory after use)

~~~bash
scripts/dev-transfer.sh clean <token>       # that token only
scripts/dev-transfer.sh list                # active/expired tokens (read-only)
scripts/dev-transfer.sh clean --expired     # remove tokens past their TTL
scripts/dev-transfer.sh clean --orphans     # remove interrupted/stale token dirs
scripts/dev-transfer.sh clean --all --yes   # remove every token
~~~

### 3.5 Diagnostics and throughput

~~~bash
scripts/dev-transfer.sh doctor              # keys, SSH, HTTPS, dirs, disk, expected rates
scripts/dev-transfer.sh speedtest --size-mb 24   # push+fetch+clean round trip with sha256
~~~

## 4. Command reference

~~~text
push <file> [--name NAME] [--ttl MIN] [--max-bytes N] [--ipa]
           [--vm <path-on-macOS-VM>] [--dry-run] [--json]
fetch <url> [<dest>] [--sha256 HASH] [--no-verify] [--max-bytes N] [--dry-run]
side-load <token> [--dry-run]
list
clean <token> | clean --expired | clean --orphans | clean --all --yes
doctor
speedtest [--size-mb N] [--keep]
lan push <user@host:/dest/dir/> <file>
lan fetch <user@host:/path/file> <dest> [--sha256 HASH]
~~~

Defaults: VPS root@47.115.170.160 with ~/.ssh/id_ed25519; VM
kratoshuang@127.0.0.1:2222 with ~/.ssh/3ds2apple_macos; TTL 180 min; max 2 GiB per
artifact. Override with DT_VPS_TARGET, DT_VPS_KEY, DT_VPS_PORT, DT_VM_TARGET, DT_VM_KEY,
DT_VM_PORT, DT_TMP_ROOT, DT_INDEX_DIR, DT_BASE_URL, DT_TTL_MINUTES, DT_MAX_BYTES.
Use **--dry-run** to print the exact steps without creating a token or touching the VPS.

Where files land on the VPS:

~~~text
/var/www/ios/tmp/<token>/<name>          served at https://<vps>/ios/tmp/<token>/<name>
/var/www/ios/tmp/<token>/<name>.sha256   non-secret verification sidecar
/var/www/ios/tmp/<token>/source.json     only for --ipa (SideStore source)
/var/lib/dev-transfer/<token>.json       index metadata, root-only (not web-served)
~~~

## 5. Security and cleanup policy

- Tokens are **random 96-bit hexpath segments** (openssl rand -hex 12), not passwords.
  The URL is unauthenticated: treat it as a secret and never paste it into issues, chat or
  commits. Anyone with the exact URL can download for the TTL window.
- Every artifact is **sha256-verified on push (remote hash) and on fetch (local hash)**.
- Default TTL is 180 min; **every token must be cleaned** with clean after the install,
  and stale tokens are removable with clean --expired / --orphans.
- Never publish bundled-ROM IPAs on a public GitHub release or any permanent URL; use this
  one-time path only for the user's own device, then delete it.
- The script never prints keys, passwords or Apple credentials; the VPS key path stays
  local. Never commit ROM/IPA content, generated C, or the local IPA/ directory.
- nginx access logs on the VPS contain the token path; the VPS is root-only, but deleting
  the token directory is what makes the artifact unreachable.
- iPhone/SideStore signing stays on the device (SideStore); this helper only moves bytes.

## 6. Getting a fast path (recommended fixes, in order)

The measured bottleneck is the VPS egress cap. Options, fastest first:

1. **Same LAN (fastest, ~15 s for 1.5 GB).** Put the CachyOS build machine and the
   Windows PC on the same network (both on the same Wi-Fi or both on the same Ethernet
   switch; currently CachyOS is on 192.168.1.0/24 and Windows on 192.168.10.0/24 with no
   route between them and neither machine has a reachable inbound port). Then:
   ~~~bash
   # Windows/WSL -> CachyOS (or reverse), direct rsync, no VPS:
   scripts/dev-transfer.sh lan fetch kratos@192.168.1.8:~/3ds2apple/IPA/<name>.ipa IPA/<name>.ipa
   ~~~
   At gigabit Ethernet this is ~15 s for 1.5 GB; Wi-Fi 5 is ~30-60 s. The existing
   user workaround is to plug the CachyOS host into the same router as the Windows PC or
   to move the build VM onto the Windows machine.
2. **VPS with more egress bandwidth (one-command relay, ~5-7 min for 1.5 GB).** The
   current instance allows only ~4 Mbps outbound (measured 0.19-0.42 MB/s); the upload direction
   already reaches 4.7-4.9 MB/s. Upgrading the VPS to 50 Mbps egress (or adding a
   bandwidth package / switching to a pay-by-traffic CVM) would make the relay
   ~4.7 MB/s in both directions: 1.5 GB in about (push 5.3 min) + (fetch ~4-5 min).
   No script change is needed; the same commands then deliver ~5-7 min end to end.
3. **Alternative relay with good egress** (object storage/CDN with a random one-time
   path): keep the same push/fetch interface by pointing DT_TMP_ROOT/DT_BASE_URL at the
   new host. This must be the user's own storage - never a public file-sharing service for
   ROM-containing IPAs.
4. **Direct IPv6 from CachyOS to an IPv6-capable iPhone** is theoretically possible (the
   CachyOS host has a public IPv6 address and the home uplink is 4.7-4.9 MB/s), but
   inbound reachability was not verified and WSL has no global IPv6, so this is not
   implemented or recommended here.

Until one of those is in place, plan for 1.1-2.3 h for a 1.5 GB artifact: run the push
first (6-9 min), then start the fetch and leave it running; it is resumable.
**Do not transfer the 1.5 GB bundled-ROM IPA unless the user explicitly asks for it.**

## 7. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| push: cannot SSH to root@47.115.170.160 | Run push on the CachyOS host (it has ~/.ssh/id_ed25519); fetch runs anywhere |
| push: --vm ... cannot SSH to the macOS VM | Start the VM / use a local file; VM must be reachable at localhost:2222 |
| fetch prints sha256 mismatch | Do not use the file. Remove it and retry; if the remote copy is wrong, re-push |
| fetch interrupt (Ctrl-C, network) | Rerun the same command; curl -C - resumes; verify passes at the end |
| 403 on /ios/tmp/ | Expected: nginx autoindex off, directory listings are disabled |
| 404 on the artifact URL | Token was cleaned or expired; push again |
| qemu VM asleep | Handoff: start caffeinate in the VM; if QEMU is paused use system_reset |
| list shows EXPIRED | Token past TTL; run clean --expired |
| push exits on --max-bytes | Default cap is 2 GiB; pass a larger --max-bytes only for an intended transfer |
